## 4. Децентрализация — что где (больше не спорить)

| Что делает пользователь | Нужен банк / наш кассир? | Где данные |
|-------------------------|---------------------------|------------|
| Собрать древо, править, автосохранение | **Нет** | Браузер |
| PDF, почта, печать | **Нет** | Устройство |
| **Открыть уже сохранённое** по 12 словам | **Нет** | Arweave + расшифровка на устройстве |
| Первый раз **оплатить** «навсегда» тенге/Kaspi | **Да** (только этот шаг) | Банк проверяет оплату; в Arweave уходит уже шифр |
| Сайт приложения | **Нет** как «наш обычный хостинг» | **Arweave** + `sejire.ar.io` |

### Жёсткое правило

- **Сайт и сейфы** — децентрализованно (Arweave).
- **Приём тенге** — всегда через банк; полностью «на Arweave» оплату картой/Kaspi сделать нельзя.
- Допустимый компромисс: **крошечный кассир** (Worker и т.п.) **только** «оплата прошла?» → залить ciphertext. Он **не** хранит род и **не** видит 12 слов.
- Кассир **не является** «основным сайтом продукта». Основной сайт — permaweb.

### Открытие уже сохранённого (зафиксированный сценарий)

1. Открыть SEJIRE (предпочтительно `sejire.ar.io`).
2. Ввести 12 слов.
3. Клиент сам считает ключ и `vaultId`.
4. Ищет envelope в Arweave по тегу `Vault-Id` (через любой шлюз сети).
5. Скачивает ciphertext и расшифровывает **только на устройстве**.

**Не нужны:** Kaspi, Stripe, Cloudflare, аккаунт SEJIRE, email.

Шлюз (gateway) — только «дверь» к Arweave; данные не у SEJIRE на сервере. Дверь можно сменить.

Спека: [`security/SEED_ACCESS.md`](./security/SEED_ACCESS.md), flow [`flows/07-seed-access.md`](./flows/07-seed-access.md).
